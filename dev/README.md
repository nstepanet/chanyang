# 개발용 도구

이 폴더는 앱을 고칠 때 쓰는 검사와 도구입니다. **앱에는 들어가지 않습니다.** 성도들의 휴대폰이 받는 파일이 아니고, 앱의 어느 화면도 이 폴더를 부르지 않습니다.

- 지금 상태와 남은 일: [`STATUS.md`](STATUS.md)
- 일하는 방식과 규칙: 저장소 맨 위의 [`CLAUDE.md`](../CLAUDE.md)

## 준비 (처음 한 번)

Node 22 이상이 필요합니다. `node -v` 로 확인합니다.

```
cd dev
npm install
```

화면 점검(`audit`, `sw-check`)은 이 컴퓨터에 깔려 있는 Chrome 이나 Edge 를 창 없이 띄워서 씁니다. 따로 내려받는 것은 없습니다. 찾지 못하면 `CHROME_PATH` 환경 변수에 실행 파일 경로를 적습니다.

## 자동 검사

```
npm test                  전부 (40초쯤)
npm test -- theme         이름에 theme 이 들어간 묶음만
npm test -- -v            통과한 줄까지 모두 보기
```

| 묶음 (`tests/`) | 확인하는 것 |
|---|---|
| `sql-1-setup` | 1단계 서버 설정: 글·사진 표, 누가 읽고 쓸 수 있는지, 관리자 추가·제외 |
| `sql-2-members` | 2단계 성도 승인: 승인번호 만들기·입력·만료·잠금, 승인된 휴대폰만 읽기, 끄고 켜기 |
| `sql-3-theme` | 3단계 화면 디자인: 누구나 읽기, 관리자만 바꾸기, 여러 번 실행해도 안전한지 |
| `app-1-posts` | 앱: 글 올리기·지우기, 관리자 로그인, 주보 사진 (성도 승인 전의 서버) |
| `app-2-members` | 앱: 승인번호 입력 화면, 성도 승인 화면, 비공개 사진, 설치 안내 |
| `app-3-theme` | 앱: 서버가 정한 디자인 따르기, 관리자의 디자인 고르기, 꾸밈 파일·글꼴·대비 |
| `copy-page` | 서버 설정 복사 페이지: 원본이 글자 하나 다르지 않게 복사되는지 |
| `icons-sw` | 아이콘 파일, 휴대폰 보관(서비스 워커)의 규칙 |
| `server-status` | 서버 상태 읽기 도구가 읽기만 하는지 |

- `sql-*` 은 실제 Postgres(PGlite)를 이 컴퓨터 안에서 띄워 `supabase/*.sql` 을 그대로 돌립니다. 실제 서버와는 상관없습니다.
- `app-*` 은 앱 파일(`index.html`, `app.js`, `server.js`, 진짜 Supabase 라이브러리)을 가상 브라우저(jsdom)에 올리고, 서버 자리에 가짜 서버(`tests/harness.js`)를 둡니다. 서버 쪽 동작을 바꾸면 이 가짜 서버도 같이 고쳐야 합니다.
- 실패한 줄만 보여 줍니다. 한 묶음만 자세히 보려면 `node tests/app-3-theme.test.js` 처럼 직접 돌립니다.

## 화면 디자인 고치기

`app.css` 는 두 부분입니다.

- 앞부분: 기본 모양. **클래식 화면**은 이 모양 그대로입니다. 직접 고칩니다.
- "화면 디자인" 표시 아래: `themes/` 의 원본으로 **만들어진** 부분입니다. 직접 고치지 않습니다.

| 원본 (`themes/`) | 내용 |
|---|---|
| `shared.css` | 세 디자인이 함께 쓰는 규칙 (디자인 고르기 화면 등). 그대로 들어감 |
| `bright.css` | 밝은 화면. 규칙마다 앞에 `html[data-theme="bright"]` 가 붙어서 들어감 |
| `warm.css` | 따뜻한 화면. 규칙마다 앞에 `html[data-theme="warm"]` 이 붙어서 들어감 |

```
npm run themes            원본으로 app.css 를 다시 만듦
npm run themes:check      고치지 않고, 어긋났는지만 확인 (자동 검사에도 들어 있음)
```

원본은 접두어 없이 평범한 규칙으로 씁니다. `:root` 는 그 디자인의 `<html>`, `body` 는 그 디자인의 `<body>` 가 됩니다. 좁은 화면용 규칙은 `@media (max-width: …px) { … }` 로 묶고, 주석은 줄을 따로 씁니다.

## 미리보기

```
npm run preview
```

`http://127.0.0.1:8765/?theme=warm&open=1&tab=home` 처럼 엽니다. 서버 자리에 가짜 서버(`preview/preview-stub.js`)를 끼워서 **실제 서버에는 아무것도 보내지 않습니다.** 주소 뒤에 붙이는 값으로 상황을 고릅니다(디자인, 승인된 휴대폰, 관리자, 화면, 글 없음 등). 값의 목록은 `preview/preview-stub.js` 맨 위에 있습니다.

`npm run preview -- --real` 은 앱 그대로 띄웁니다. 실제 서버에 연결되므로 글을 올리거나 승인번호를 넣지 않습니다.

## 화면 점검

```
npm run audit                                    세 디자인 × 폭 390·360·320 × 화면 21개 (5분쯤)
npm run audit -- bright,warm 360                 디자인과 폭을 골라서
npm run audit -- warm 360 --only 04-home         화면을 골라서
npm run audit -- bright 360 --shots              화면도 찍음 → dev/out/shots/bright-360/
```

- **문제**(가로로 넘침, 화면 밖으로 나감, 글자가 잘리거나 삐져나옴, 그림 깨짐, 받지 못한 파일, 오류)가 하나라도 있으면 실패로 끝납니다.
- **참고**(두 줄로 꺾인 단추 글자, 낮은 누르는 곳)는 보기만 합니다. 지금 나오는 참고는 모두 알고 있는 것입니다: 클래식 화면 홈의 "부천역 8분"(원래 모습), 폭 320 에서 두 줄이 되는 긴 제목과 단추.
- 숫자로 못 잡는 것(어색한 줄바꿈, 색, 간격)은 찍은 화면을 직접 봐야 합니다.
- 화면을 새로 만들면 `preview/audit.mjs` 의 `SCREENS` 에 한 줄 더합니다.

```
npm run sw-check
```

휴대폰 보관(서비스 워커)이 설치되고 보관 목록을 모두 받는지, 글꼴을 따로 보관하는지, 설치 정보와 아이콘에 오류가 없는지, 인터넷이 끊겨도 화면과 글꼴이 나오는지 봅니다. 끝에 디자인마다 처음 받는 글꼴의 양도 보여 줍니다.

## 실제 서버 상태 읽기

```
npm run server-status
```

실제 서버에 2단계(성도 승인), 3단계(화면 디자인) 설정이 되어 있는지와 지금 값을 보여 줍니다. 읽기만 하고, 로그인하지 않으며, 아무것도 바꾸지 않습니다. 앱을 처음 여는 휴대폰이 서버에 보내는 것과 같은 두 가지 질문입니다.

## 이 폴더에 없는 것

- 내려받은 도구(`node_modules/`)와 찍은 화면(`out/`)은 저장소에 올리지 않습니다(`.gitignore`).
- 아이콘과 십자가 그림을 만드는 도구, 그 원본 그림은 저장소에 없습니다. 저장소 주인이 따로 가지고 있습니다. 아이콘을 다시 만들 일이 생기면 주인에게 그 묶음을 받습니다.
