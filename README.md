# 찬양하는교회 웹앱

부천 찬양하는교회 성도를 위한 설치형 웹앱(PWA)입니다. 화면은 GitHub Pages 에서, 글과 주보 사진은 Supabase 서버에서 제공합니다.

## 들어 있는 기능

- 홈: 오늘의 말씀, 생명의 삶 QT 연결, 최근 주일예배, 교회 소식
- 설교: 유튜브 예배 영상 841개 (주일예배 / 주일저녁예배 / 금요심야기도회, 연·월별), 설교 노트
- 소식·주보·일정: 관리자가 앱에서 올리면 모든 성도에게 보입니다 (주보 사진 첨부 가능)
- 관리자 로그인, 글 올리기·지우기, 전체 내용 내려받기(백업)
- 성도 승인: 관리자가 문자로 보낸 승인번호를 입력한 휴대폰만 글과 주보 사진을 볼 수 있습니다 (서버 설정 2단계를 실행한 뒤부터)
- 새 글이 올라오면 종 모양에 점 표시
- 기도제목
- 예배 시간, 오시는 길, 새가족 안내
- 홈 화면 설치, 인터넷이 끊겨도 마지막으로 본 내용 표시

## 앱 주소

https://nstepanet.github.io/chanyang/

## 어디에 올려야 앱에 반영되나

이 앱은 저장소의 **`gh-pages` 브랜치**에 있는 파일로 서비스됩니다. `main` 브랜치에는 같은 파일의 사본이 있습니다.

- 파일을 고칠 때는 **`gh-pages` 브랜치**에 올려야 앱에 반영됩니다. (GitHub 화면 왼쪽 위의 브랜치 버튼에서 `gh-pages` 를 고른 뒤 파일을 수정하거나 올립니다.)
- `main` 에만 올리면 앱은 바뀌지 않습니다. 두 브랜치를 같은 내용으로 맞춰 두면 헷갈리지 않습니다.
- 올린 뒤 1~2분이면 주소에 반영됩니다.

## 휴대폰에 설치하는 방법

- 아이폰: Safari 로 주소를 연 뒤 공유 버튼 → "홈 화면에 추가"
- 안드로이드: Chrome 으로 주소를 연 뒤 화면의 "앱 설치하기" 단추, 또는 메뉴(⋮) → "앱 설치" / "홈 화면에 추가"
- 카카오톡으로 받은 주소는 카카오톡 안의 화면에서 열려 설치가 되지 않습니다. 화면의 안내 단추로 Chrome 이나 Safari 에서 다시 엽니다.

아이폰은 Safari 와 홈 화면 앱의 저장 공간이 따로라서, **승인번호는 홈 화면에 설치한 앱에서 입력**해야 합니다. (앱이 Safari 에서는 설치 안내만 보여 줍니다.)

## 내용 고치기

| 고칠 것 | 어디서 |
|---|---|
| 소식, 주보, 일정 | 앱에서 관리자로 로그인 → 글 올리기 |
| 공동 기도제목, 서버에 연결되지 않을 때 보여 줄 기본 글 | `data/content.json` |
| 예배 영상 목록 | `data/videos.txt` |
| 예배 시간, 오늘의 말씀, 지도 주소 | `app.js` 맨 위의 `SETTINGS` |
| 서버 주소와 공개용 키 | `config.js` |
| 교회 건물 사진 | `img/church-building.jpg` |

파일을 고친 뒤에는 `sw.js` 맨 위의 `VERSION` 값을 `v2`, `v3` 처럼 올려 주세요. 그래야 이미 설치한 휴대폰에도 새 화면 파일이 확실히 받아집니다. (`data/` 안의 파일만 고쳤다면 올리지 않아도 됩니다.)

### data/videos.txt 형식

`연월일:종류+영상ID,종류+영상ID;` 를 이어 붙인 한 줄입니다. 종류는 `A` 주일예배, `B` 주일저녁예배, `C` 금요심야기도회입니다. 영상 ID 뒤의 `!` 는 비공개 영상 표시입니다.

예: `261115:AnoUNXF2j-uY,BW8DSejnlh7c;` → 2026년 11월 15일의 주일예배와 주일저녁예배

## 서버 (Supabase)

### 파일 구성

| 파일 | 역할 |
|---|---|
| `config.js` | 서버 주소(Project URL)와 공개용 키(Publishable key). 둘 다 공개되어도 되는 값입니다. |
| `server.js` | 서버와 통신하는 코드 전부. 서버를 다른 것으로 바꾸면 이 파일만 다시 쓰면 됩니다. |
| `vendor/supabase.js` | Supabase 브라우저 라이브러리 (@supabase/supabase-js, MIT 라이선스) |
| `supabase/setup.sql` | 1단계 설정: 서버에 표·접근 규칙·사진 저장 공간을 만듭니다 |
| `supabase/members.sql` | 2단계 설정: 성도 승인 (승인번호, 명단, 승인된 휴대폰만 읽기) |
| `supabase/index.html` | 위 설정을 번역 영향 없이 단추 한 번으로 복사하는 페이지 |

`sb_secret_` 로 시작하는 Secret key 와 Database Password 는 이 저장소 어디에도 넣지 마세요.

### 처음 설정하는 순서

1. Supabase 대시보드 → **Authentication → Users → Add user → Create new user** 에서 관리자 계정(이메일, 비밀번호)을 만듭니다. "Auto Confirm User" 는 켠 채로 둡니다.
2. https://nstepanet.github.io/chanyang/supabase/ 를 열어 **서버 설정 내용 복사하기** 단추를 누른 뒤, **SQL Editor** 에 붙여 넣고 **Run** 을 누릅니다. 결과 표의 "관리자 계정"에 1번의 이메일이 보이면 끝입니다.
   - 브라우저 자동 번역이 켜진 상태에서 GitHub 화면의 SQL 을 직접 복사하면 문장이 한국어로 바뀌어 오류가 납니다. 꼭 위 단추로 복사하세요.
3. 성도 승인을 쓰려면 아래 "성도 승인" 순서대로 2단계 설정을 실행합니다.

### 관리자를 추가하거나 빼기

1번처럼 계정을 먼저 만든 뒤 SQL Editor 에서 실행합니다.

```sql
select app_private.add_admin('새관리자@example.com');     -- 추가
select app_private.remove_admin('그만둘분@example.com');  -- 제외
```

### 성도 승인 (2단계 설정)

관리자가 승인한 휴대폰만 글과 주보 사진을 볼 수 있게 하는 기능입니다. 앱 설치는 누구나 할 수 있지만, 승인번호를 입력하기 전에는 승인번호 입력 화면만 보입니다.

**켜는 순서**

1. Supabase 대시보드 → **Authentication → Sign In / Providers** 에서 "Allow new users to sign up" 과 "Allow anonymous sign-ins" 를 켭니다. (승인번호를 입력하는 휴대폰마다 서버가 이름표 구실을 하는 임시 계정을 하나 만들기 때문에 필요합니다. 가입만으로는 아무 권한도 생기지 않습니다.)
2. https://nstepanet.github.io/chanyang/supabase/ 에서 **2단계 설정 내용 복사하기** 단추를 누른 뒤, SQL Editor 에 붙여 넣고 Run 을 누릅니다. 결과 표의 "성도 승인"에 "켜짐"이 나오면 끝입니다.
3. 실행한 순간부터 승인받지 않은 휴대폰은 내용을 볼 수 없습니다. 관리자로 로그인한 휴대폰은 승인번호 없이 볼 수 있습니다.

**승인하는 방법 (앱에서)**

1. 관리자로 로그인 → **더보기 → 성도 승인**
2. 성도 이름을 적고 **승인번호 만들기** → **문자 보내기** (문자 앱이 승인번호와 앱 주소가 적힌 채로 열립니다. 받는 사람을 고르고 보냅니다.) 카카오톡 등으로 보내려면 **내용 복사**를 씁니다.
3. 성도가 앱을 설치하고 승인번호를 입력하면 명단에 "승인"으로 바뀝니다.

**알아 둘 점**

- 승인번호는 숫자 8자리, 한 번만 쓸 수 있고 7일 동안 유효합니다. 5번 틀리면 그 휴대폰은 1시간 동안 입력이 잠깁니다.
- 승인번호는 만든 직후에만 볼 수 있고 서버에는 남지 않습니다. 놓쳤으면 명단에서 **다시 보내기**로 새 번호를 만듭니다.
- 승인은 "그 휴대폰의 그 앱"에 붙습니다. 휴대폰을 바꾸거나 앱 데이터를 지운 성도에게는 **다시 보내기**로 새 번호를 보냅니다. 새 번호를 입력하면 예전 휴대폰의 승인은 풀립니다.
- 한 사람이 휴대폰과 태블릿을 함께 쓰려면 명단에 두 줄로 넣습니다. (예: "홍길동", "홍길동 태블릿")
- **승인 취소**를 누르면 그 휴대폰은 다음에 서버에 확인할 때 바로 잠기고, 받아 둔 글도 지워집니다.
- 전화번호는 서버에 저장하지 않습니다. 서버에는 이름과 승인 기록만 남습니다.
- 예배 영상 목록(`data/videos.txt`)과 `data/content.json` 은 공개 파일이라 승인과 관계없이 주소를 아는 사람은 받을 수 있습니다. 승인 전 화면에서는 보이지 않습니다.

**잠시 끄거나 다시 켜기** (SQL Editor 에서 한 줄 실행, 명단은 그대로 남습니다)

```sql
select app_private.set_members_only(false);  -- 끄기: 승인 없이 누구나 볼 수 있음
select app_private.set_members_only(true);   -- 켜기: 승인된 휴대폰과 관리자만
```

### 누가 무엇을 할 수 있나

성도 승인을 켠 상태 기준입니다. (끄면 글·사진 읽기가 모두 "가능"이 됩니다.)

| | 글·주보 사진 읽기 | 글 올리기·지우기 | 사진 올리기·지우기 | 승인번호 만들기·명단 |
|---|---|---|---|---|
| 승인받지 않은 휴대폰 | 불가 | 불가 | 불가 | 불가 |
| 승인된 휴대폰 | 가능 | 불가 | 불가 | 불가 |
| 관리자 | 가능 | 가능 | 가능 | 가능 |

이 규칙은 앱이 아니라 서버(데이터베이스)에서 지킵니다.

### 백업과 이사

- 앱의 **더보기 → 전체 내용 내려받기 (백업)** 으로 모든 글을 파일 하나로 받을 수 있습니다. 무료 요금제에는 자동 백업이 없으니 가끔 받아 두세요.
- 무료 요금제는 일주일 동안 사용이 없으면 프로젝트가 멈춥니다. 멈추면 Supabase 대시보드에서 다시 켜면 되고, 그동안 앱은 마지막으로 받아 둔 글을 보여 줍니다.
- 다른 서버로 옮길 때는 데이터베이스를 내보내고, `post-images` 저장 공간의 사진을 옮긴 뒤, `config.js`(같은 종류의 서버) 또는 `server.js`(다른 종류의 서버)를 바꿉니다. 새 Supabase 서버라면 1단계 → 2단계 설정을 차례로 실행합니다.
- 백업 파일에는 글과 성도 명단(이름, 승인 상태)이 들어갑니다. 승인번호와 휴대폰별 승인은 옮겨지지 않으므로, 서버를 옮기면 승인번호를 다시 보내야 합니다.
- 성도 승인을 켠 뒤에는 주보 사진이 공개 주소로 열리지 않습니다. 사진 원본은 Supabase 대시보드의 Storage 에서 내려받습니다.

## 아직 안 되는 것 (다음 단계에서 추가)

- 기도제목은 각자 휴대폰에만 저장되고 서로 나눠지지 않습니다.
- 실제 푸시 알림은 가지 않습니다. (앱을 열면 종 모양의 점으로 새 글을 알려 줍니다.)
- 새 예배 영상이 자동으로 추가되지 않습니다.
