# 찬양하는교회 웹앱

부천 찬양하는교회 성도를 위한 설치형 웹앱(PWA)입니다. 화면은 GitHub Pages 에서, 글과 주보 사진은 Supabase 서버에서 제공합니다.

## 들어 있는 기능

- 홈: 오늘의 말씀, 생명의 삶 QT 연결, 최근 주일예배, 교회 소식
- 설교: 유튜브 예배 영상 844개 (주일예배 / 주일저녁예배 / 금요심야기도회, 연·월별), 설교 노트, 설교 요약과 "설교 부분부터 보기"(정리 자료가 있는 영상만)
- 나에게 맞는 말씀 찾기: 설교 탭에서 내 상황을 적거나 마음 단추를 누르면 맞는 설교를 3편까지 권해 줍니다. 찾기는 휴대폰 안에서만 하고, 적은 글은 어디에도 보내지 않습니다.
- 소식·주보·일정: 관리자가 앱에서 올리면 모든 성도에게 보입니다 (주보 사진 첨부 가능)
- 관리자 로그인, 글 올리기·지우기, 전체 내용 내려받기(백업)
- 성도 승인: 관리자가 문자로 보낸 승인번호를 입력한 휴대폰만 글과 주보 사진을 볼 수 있습니다 (서버 설정 2단계를 실행한 뒤부터)
- 화면 디자인 세 가지 (밝은 화면 · 따뜻한 화면 · 클래식 화면): 관리자가 고르면 모든 성도의 휴대폰이 그 디자인으로 바뀝니다 (서버 설정 3단계를 실행한 뒤부터)
- 새 글이 올라오면 종 모양에 점 표시
- 기도제목: 각자 휴대폰에만 저장. 내가 적은 기도에 맞는 설교가 있으면 그 아래에 "이 기도에 힘이 되는 설교" 한 편을 보여 줍니다(역시 휴대폰 안에서만 찾음).
- 예배 시간, 오시는 길, 새가족 안내
- 홈 화면 설치, 인터넷이 끊겨도 마지막으로 본 내용 표시

## 앱 주소

https://nstepanet.github.io/chanyang/

## 어디에 올려야 앱에 반영되나

이 앱은 저장소의 **`gh-pages` 브랜치**에 있는 파일로 서비스됩니다. `main` 브랜치에는 같은 파일의 사본이 있습니다.

- 파일을 고칠 때는 **`gh-pages` 브랜치**에 올려야 앱에 반영됩니다. (GitHub 화면 왼쪽 위의 브랜치 버튼에서 `gh-pages` 를 고른 뒤 파일을 수정하거나 올립니다.)
- `main` 에만 올리면 앱은 바뀌지 않습니다. 두 브랜치를 같은 내용으로 맞춰 두면 헷갈리지 않습니다.
- 올린 뒤 1~2분이면 주소에 반영됩니다.

## 휴대폰에 설치하는 방법

- 아이폰: Safari 로 주소를 연 뒤 공유 버튼 → "홈 화면에 추가"
- 안드로이드: Chrome 으로 주소를 연 뒤 화면의 "앱 설치하기" 단추, 또는 메뉴(⋮) → "앱 설치" / "홈 화면에 추가"
- 카카오톡으로 받은 주소는 카카오톡 안의 화면에서 열려 설치가 되지 않습니다. 화면의 안내 단추로 Chrome 이나 Safari 에서 다시 엽니다.

아이폰은 Safari 와 홈 화면 앱의 저장 공간이 따로라서, **승인번호는 홈 화면에 설치한 앱에서 입력**해야 합니다. (앱이 Safari 에서는 설치 안내만 보여 줍니다.)

| 고칠 것 | 어디서 |

| 소식, 주보, 일정 | 앱에서 관리자로 로그인 → 글 올리기 |

| 공동 기도제목, 서버에 연결되지 않을 때 보여 줄 기본 글 | `data/content.json` |
| 예배 영상 목록 | `data/videos.txt` |
| 설교 요약 (설교 시작 시간, 세 줄 요약, 흐름, 주제) | `data/sermons.json` |
| 예배 시간, 오늘의 말씀, 지도 주소 | `app.js` 맨 위의 `SETTINGS` |
| 서버 주소와 공개용 키 | `config.js` |
| 교회 건물 사진 | `img/church-building.jpg` |
| 승인 화면 맨 위의 십자가 그림 | `img/cross.jpg` (정사각형, 384×384). 따뜻한 화면에서는 이 자리에 `img/cross-mark.png` 가 아치 모양 안에 보입니다. |
| 다섯 탭의 제목 앞에 보이는 작은 십자가 | `img/cross-mark.png` (바탕이 투명한 그림, 크기는 `app.css` 의 `h1.mark`). 따뜻한 화면에서는 같은 그림이 초록색으로, 밝은 화면에서는 이 자리에 앱 아이콘이 보입니다. 홈의 "최근 예배" 카드에도 이 그림을 씁니다. |
| 디자인마다 다른 색·글꼴·모양 | `app.css` 의 "화면 디자인" 부분 (아래 "화면 디자인" 참고) |
| 홈 화면 아이콘, 브라우저 탭 아이콘 | `icons/` 안의 그림 5개 (아래 "아이콘을 바꿀 때" 참고) |

파일을 고친 뒤에는 `sw.js` 맨 위의 `VERSION` 값을 `v2`, `v3` 처럼 올려 주세요. 그래야 이미 설치한 휴대폰에도 새 화면 파일이 확실히 받아집니다. (`data/` 안의 파일만 고쳤다면 올리지 않아도 됩니다.)

### 아이콘을 바꿀 때

아이콘 그림은 `icons/` 에 있습니다.

| 파일 | 쓰이는 곳 | 크기 |
|---|---|---|
| `icon-192-v3.png`, `icon-512-v3.png` | 안드로이드 홈 화면·설치 창 | 192, 512 |
| `icon-maskable-512-v3.png` | 안드로이드에서 둥글게 잘라 보여 주는 아이콘 (십자가를 가운데 80% 원 안에 둠) | 512 |
| `apple-touch-icon-v3.png` | 아이폰 홈 화면 | 180 |
| `favicon-32-v3.png` | 브라우저 탭 | 32 |

그림을 바꿀 때는 **파일 이름도 함께 바꿔 주세요** (`-v3` → `-v4`). 이름이 그대로면 이미 설치한 휴대폰은 그림이 바뀐 것을 알아차리지 못합니다. 바꾼 이름은 `manifest.webmanifest`, `index.html`, `sw.js`, `app.css`(밝은 화면의 제목 앞 그림. 원본은 `dev/themes/bright.css`) 네 곳에 똑같이 적고, `sw.js` 의 `VERSION` 도 올립니다.

이미 설치한 휴대폰의 아이콘은 바로 바뀌지 않습니다. 안드로이드는 앱을 다시 열 때 브라우저가 바뀐 아이콘을 알아차리고 사용자에게 확인을 받은 뒤 바꾸며, 아이폰은 홈 화면에서 지우고 다시 설치해야 바뀝니다.

### data/videos.txt 형식

`연월일:종류+영상ID,종류+영상ID;` 를 이어 붙인 한 줄입니다. 종류는 `A` 주일예배, `B` 주일저녁예배, `C` 금요심야기도회입니다. 영상 ID 뒤의 `!` 는 비공개 영상 표시입니다.

예: `261115:AnoUNXF2j-uY,BW8DSejnlh7c;` → 2026년 11월 15일의 주일예배와 주일저녁예배

### data/sermons.json 형식

영상마다 설교 부분을 정리한 자료입니다. 자료가 있는 영상은 설교 화면에 "설교 부분부터 보기" 단추와 요약 카드가 생기고, 없는 영상은 지금처럼 영상과 노트만 보입니다. 설교 탭의 "나에게 맞는 말씀 찾기"와 기도제목 아래의 "이 기도에 힘이 되는 설교"도 이 자료로 찾습니다(`app.js` 의 `matchSermons`). 성도가 적은 문장을 설교마다 미리 적어 둔 상황 문장(`situations`)과 글자 조각으로 비교해 가장 비슷한 설교를 고르고, 찾는 말(`keywords`)과 주제(`topics`)가 걸리면 점수를 더합니다. 자료 파일이 없으면 이 두 가지는 화면에 나오지 않고, `situations` 가 없는 설교는 찾는 말과 주제로만 찾습니다.

- `topics`: 주제 목록. `id`, 화면에 보일 `name`, 성도가 적을 만한 낱말 `words`.
- `sermons`: 설교마다 영상 `id`(`videos.txt` 에 있는 것), `date`, `type`, 설교가 시작하고 끝나는 `start`·`end`(`분:초` 또는 `시:분:초`), `title`, `series`, 봉독 본문 `reading`, 인용 구절 `verses`, 세 줄 요약 `summary`, 대지별 흐름 `outline`(`h` 제목, `t` 내용), 이번 주에 해 볼 일 `todo`, 주제 `topics`(topics 의 id), 찾는 말 `keywords`, 상황 문장 `situations`(이 설교가 힘이 될 처지·마음·바람을 성도의 말투로 30개쯤. "아들이 직장을 못 구해 마음이 무거워요"), 참고 `note`.

찾는 방법(`matchSermons`): 조사·말끝을 떼고("아들이"→"아들", "걱정이에요"→"걱정"), 때·정도·기도문의 상투어("오늘", "너무", "위해", "기도", "하나님")는 빼고, 글자 두 개 조각과 자음·모음 세 개 조각(말끝이 달라도 맞게)으로 비교합니다. 조각은 드문 것일수록 무겁게 칩니다. 가장 비슷한 상황 문장과의 비슷함과 설교 전체에 덮인 비율의 기하평균이 0.3 이상이면 ×15 점, 찾는 말은 하나에 3점(세 개까지), 글에서 찾은 주제는 2점, 마음 단추의 주제는 4점입니다. 검사 `dev/tests/app-5-match.test.js` 에 시험 문장 40개가 있어 바꿀 때 몇 개를 맞히는지 봅니다.

유튜브 자동 자막을 바탕으로 정리하므로 화면에도 그렇게 적어 둡니다. 성도의 이름은 넣지 않습니다. 이 파일만 고쳤을 때는 `sw.js` 의 `VERSION` 을 올리지 않습니다.

## 화면 디자인

앱의 모양은 세 가지가 들어 있고, 교회 전체가 한 가지를 함께 씁니다.

| 이름 | 서버·코드에서 쓰는 값 | 모양 |
|---|---|---|
| 밝은 화면 (처음 값) | `bright` | 밝은 바탕, 큰 제목, 파란색 포인트 |
| 따뜻한 화면 | `warm` | 크림색 바탕, 명조 제목, 초록색 포인트 |
| 클래식 화면 | `classic` | 남색 띠가 있는 처음 디자인 |

**고르는 방법**

- 관리자로 로그인 → **더보기 → 화면 디자인** 에서 하나를 누릅니다. 관리자만 바꿀 수 있고, 고른 디자인은 **성도 모두의 휴대폰**에 적용됩니다. (승인번호를 넣기 전의 화면도 같은 디자인으로 보입니다.)
- 다른 휴대폰은 앱을 다시 열 때 바뀝니다. 앱을 켜 둔 채 다른 일을 하다가 1분 넘게 지나 돌아와도 바뀝니다.
- 인터넷이 끊겨 있으면 마지막으로 받은 디자인 그대로 보입니다.
- 이 기능은 서버 설정 3단계(`supabase/theme.sql`)를 실행한 뒤부터 쓸 수 있습니다. 실행하기 전에는 모든 휴대폰이 밝은 화면으로 보이고, 화면 디자인 메뉴에는 설정 안내가 나옵니다. 순서는 아래 "화면 디자인 (3단계 설정)"에 있습니다.
- 홈 화면의 앱 아이콘은 디자인과 관계없이 남색 그대로입니다.

**어느 파일에 들어 있나**

| 파일 | 들어 있는 것 |
|---|---|
| `app.css` 앞부분 | 기본 모양. 클래식 화면은 이 모양 그대로입니다. |
| `app.css` 뒷부분 ("화면 디자인" 표시 아래) | 밝은 화면은 `html[data-theme="bright"]`, 따뜻한 화면은 `html[data-theme="warm"]` 으로 시작하는 줄이 기본 모양 위에 덧입혀집니다. 주요 색은 각 디자인의 "바탕색과 글자색" 줄에 모여 있습니다. |
| `app.js` 의 `THEMES`, `DEFAULT_THEME` | 디자인 이름·설명, 휴대폰 위쪽 띠 색, 쓰는 글꼴, 처음 값 |
| `index.html` 머리 부분의 짧은 스크립트 | 앱이 켜질 때 지난번 디자인을 먼저 입혀 화면이 깜빡이지 않게 합니다. 처음 값과 위쪽 띠 색 세 가지가 여기에도 적혀 있으니, `app.js` 를 바꾸면 같이 바꿉니다. |
| `manifest.webmanifest` 의 `background_color`, `theme_color` | 설치한 앱을 여는 순간의 바탕색 (밝은 화면의 값) |
| `fonts/` | 밝은 화면·따뜻한 화면의 글꼴 |

**글꼴**

- `fonts/pretendard` (Pretendard): 밝은 화면과 따뜻한 화면의 본문. `fonts/gowun-batang` (고운바탕): 따뜻한 화면의 제목과 말씀.
- 두 글꼴 모두 SIL Open Font License 1.1 이며, 각 폴더에 라이선스 파일(`LICENSE.txt`)이 들어 있습니다. 글꼴을 다른 곳에서 받아 오지 않고 이 저장소의 파일을 씁니다.
- 글꼴은 잘게 나뉘어 있어서(Pretendard 92개, 고운바탕 186개, 하나에 수십 KB), 그 디자인을 쓰는 휴대폰이 화면에 나온 글자가 든 묶음만 받습니다. 한 번 받은 묶음은 휴대폰에 보관되어 앱 버전이 올라가도 다시 받지 않습니다. 클래식 화면은 글꼴을 받지 않고 휴대폰의 기본 글꼴로 보입니다.
- 글꼴 파일을 바꾸면 `sw.js` 의 `FONTS` 끝 숫자를 올립니다.

**디자인을 고칠 때**

- 색이나 모양만 고칠 때는 `app.css` 의 해당 디자인 줄을 고치고 `sw.js` 의 `VERSION` 을 올립니다. 클래식 화면에 영향을 주지 않으려면 줄 맨 앞의 `html[data-theme="…"]` 를 지우지 마세요.
- 디자인 값(`bright`, `warm`, `classic`)은 `app.css`, `app.js`, `index.html`, `server.js`, `supabase/theme.sql` 에 똑같이 적혀 있습니다. 값을 더하거나 이름을 바꿀 때는 다섯 곳을 함께 고쳐야 하고, 서버 쪽도 바꿔야 합니다(이미 만든 표의 허용 값은 `theme.sql` 을 다시 실행하는 것만으로는 바뀌지 않습니다).

## 서버 (Supabase)

### 파일 구성

| 파일 | 역할 |
|---|---|
| `config.js` | 서버 주소(Project URL)와 공개용 키(Publishable key). 둘 다 공개되어도 되는 값입니다. |
| `server.js` | 서버와 통신하는 코드 전부. 서버를 다른 것으로 바꾸면 이 파일만 다시 쓰면 됩니다. |
| `vendor/supabase.js` | Supabase 브라우저 라이브러리 (@supabase/supabase-js, MIT 라이선스) |
| `supabase/setup.sql` | 1단계 설정: 서버에 표·접근 규칙·사진 저장 공간을 만듭니다 |
| `supabase/members.sql` | 2단계 설정: 성도 승인 (승인번호, 명단, 승인된 휴대폰만 읽기) |
| `supabase/theme.sql` | 3단계 설정: 화면 디자인 (관리자가 고른 디자인을 저장하고 모든 휴대폰에 알려 줌) |
| `supabase/index.html` | 위 설정을 번역 영향 없이 단추 한 번으로 복사하는 페이지 |

`sb_secret_` 로 시작하는 Secret key 와 Database Password 는 이 저장소 어디에도 넣지 마세요.

### 처음 설정하는 순서

1. Supabase 대시보드 → **Authentication → Users → Add user → Create new user** 에서 관리자 계정(이메일, 비밀번호)을 만듭니다. "Auto Confirm User" 는 켠 채로 둡니다.
2. https://nstepanet.github.io/chanyang/supabase/ 를 열어 **서버 설정 내용 복사하기** 단추를 누른 뒤, **SQL Editor** 에 붙여 넣고 **Run** 을 누릅니다. 결과 표의 "관리자 계정"에 1번의 이메일이 보이면 끝입니다.
   - 브라우저 자동 번역이 켜진 상태에서 GitHub 화면의 SQL 을 직접 복사하면 문장이 한국어로 바뀌어 오류가 납니다. 꼭 위 단추로 복사하세요.
3. 성도 승인을 쓰려면 아래 "성도 승인" 순서대로 2단계 설정을 실행합니다.
4. 화면 디자인을 앱에서 바꾸려면 아래 "화면 디자인 (3단계 설정)" 순서대로 3단계 설정을 실행합니다. (2단계를 하지 않았어도 실행할 수 있습니다.)

### 관리자를 추가하거나 빼기

```sql
select app_private.add_admin('새관리자@example.com');     -- 추가

```

### 성도 승인 (2단계 설정)

관리자가 승인한 휴대폰만 글과 주보 사진을 볼 수 있게 하는 기능입니다. 앱 설치는 누구나 할 수 있지만, 승인번호를 입력하기 전에는 승인번호 입력 화면만 보입니다.

**켜는 순서**

1. Supabase 대시보드 → **Authentication → Sign In / Providers** 에서 "Allow new users to sign up" 과 "Allow anonymous sign-ins" 를 켭니다. (승인번호를 입력하는 휴대폰마다 서버가 이름표 구실을 하는 임시 계정을 하나 만들기 때문에 필요합니다. 가입만으로는 아무 권한도 생기지 않습니다.)
2. https://nstepanet.github.io/chanyang/supabase/ 에서 **2단계 설정 내용 복사하기** 단추를 누른 뒤, SQL Editor 에 붙여 넣고 Run 을 누릅니다. 결과 표의 "성도 승인"에 "켜짐"이 나오면 끝입니다.
3. 실행한 순간부터 승인받지 않은 휴대폰은 내용을 볼 수 없습니다. 관리자로 로그인한 휴대폰은 승인번호 없이 볼 수 있습니다.

**승인하는 방법 (앱에서)**

1. 관리자로 로그인 → **더보기 → 성도 승인**
2. 성도 이름을 적고 **승인번호 만들기** → **문자 보내기** (문자 앱이 승인번호와 앱 주소가 적힌 채로 열립니다. 받는 사람을 고르고 보냅니다.) 카카오톡 등으로 보내려면 **내용 복사**를 씁니다.
3. 성도가 앱을 설치하고 승인번호를 입력하면 명단에 "승인"으로 바뀝니다.

**알아 둘 점**

- 승인번호는 숫자 8자리, 한 번만 쓸 수 있고 7일 동안 유효합니다. 5번 틀리면 그 휴대폰은 1시간 동안 입력이 잠깁니다.
- 승인번호는 만든 직후에만 볼 수 있고 서버에는 남지 않습니다. 놓쳤으면 명단에서 **다시 보내기**로 새 번호를 만듭니다.
- 승인은 "그 휴대폰의 그 앱"에 붙습니다. 휴대폰을 바꾸거나 앱 데이터를 지운 성도에게는 **다시 보내기**로 새 번호를 보냅니다. 새 번호를 입력하면 예전 휴대폰의 승인은 풀립니다.
- 한 사람이 휴대폰과 태블릿을 함께 쓰려면 명단에 두 줄로 넣습니다. (예: "홍길동", "홍길동 태블릿")
- **승인 취소**를 누르면 그 휴대폰은 다음에 서버에 확인할 때 바로 잠기고, 받아 둔 글도 지워집니다.
- 전화번호는 서버에 저장하지 않습니다. 서버에는 이름과 승인 기록만 남습니다.
- 예배 영상 목록(`data/videos.txt`)과 `data/content.json` 은 공개 파일이라 승인과 관계없이 주소를 아는 사람은 받을 수 있습니다. 승인 전 화면에서는 보이지 않습니다.

**잠시 끄거나 다시 켜기** (SQL Editor 에서 한 줄 실행, 명단은 그대로 남습니다)

```sql
select app_private.set_members_only(false);  -- 끄기: 승인 없이 누구나 볼 수 있음
select app_private.set_members_only(true);   -- 켜기: 승인된 휴대폰과 관리자만
```

### 화면 디자인 (3단계 설정)

관리자가 앱에서 고른 디자인을 서버에 저장해, 모든 휴대폰이 같은 디자인으로 보이게 하는 설정입니다.

1. https://nstepanet.github.io/chanyang/supabase/ 에서 **3단계 설정 내용 복사하기** 단추를 누른 뒤, SQL Editor 에 붙여 넣고 Run 을 누릅니다. 결과 표의 "화면 디자인"에 "밝은 화면"이 나오면 끝입니다.
2. 앱에서 관리자로 로그인 → **더보기 → 화면 디자인** 에서 디자인을 고릅니다.

- 실행해도 지금 보이는 화면과 글, 성도 명단은 그대로입니다. 여러 번 실행해도 안전하고, 이미 고른 디자인은 바뀌지 않습니다.
- 지금 디자인이 무엇인지는 승인받지 않은 휴대폰도 읽을 수 있습니다(승인 전 화면도 같은 디자인으로 보여야 하므로). 바꾸는 것은 관리자만 할 수 있습니다.

**앱을 거치지 않고 바꾸기** (SQL Editor 에서 한 줄 실행. 휴대폰에서는 앱을 다시 열면 바뀝니다.)

```sql
select app_private.set_theme('bright');   -- 밝은 화면
select app_private.set_theme('warm');     -- 따뜻한 화면
select app_private.set_theme('classic');  -- 클래식 화면
```

### 누가 무엇을 할 수 있나

성도 승인을 켠 상태 기준입니다. (끄면 글·사진 읽기가 모두 "가능"이 됩니다.)

| | 글·주보 사진 읽기 | 글 올리기·지우기 | 사진 올리기·지우기 | 승인번호 만들기·명단 | 화면 디자인 바꾸기 |
|---|---|---|---|---|---|
| 승인받지 않은 휴대폰 | 불가 | 불가 | 불가 | 불가 | 불가 |
| 승인된 휴대폰 | 가능 | 불가 | 불가 | 불가 | 불가 |
| 관리자 | 가능 | 가능 | 가능 | 가능 | 가능 |

이 규칙은 앱이 아니라 서버(데이터베이스)에서 지킵니다.

### 백업과 이사

- 앱의 **더보기 → 전체 내용 내려받기 (백업)** 으로 모든 글을 파일 하나로 받을 수 있습니다. 무료 요금제에는 자동 백업이 없으니 가끔 받아 두세요.
- 무료 요금제는 일주일 동안 사용이 없으면 프로젝트가 멈춥니다. 멈추면 Supabase 대시보드에서 다시 켜면 되고, 그동안 앱은 마지막으로 받아 둔 글을 보여 줍니다.
- 다른 서버로 옮길 때는 데이터베이스를 내보내고, `post-images` 저장 공간의 사진을 옮긴 뒤, `config.js`(같은 종류의 서버) 또는 `server.js`(다른 종류의 서버)를 바꿉니다. 새 Supabase 서버라면 1단계 → 2단계 → 3단계 설정을 차례로 실행합니다.
- 백업 파일에는 글과 성도 명단(이름, 승인 상태)이 들어갑니다. 승인번호와 휴대폰별 승인은 옮겨지지 않으므로, 서버를 옮기면 승인번호를 다시 보내야 합니다.
- 고른 화면 디자인은 백업 파일에 들어가지 않습니다. 새 서버에서는 3단계 설정을 실행한 뒤 앱에서 다시 고릅니다.
- 성도 승인을 켠 뒤에는 주보 사진이 공개 주소로 열리지 않습니다. 사진 원본은 Supabase 대시보드의 Storage 에서 내려받습니다.

## 앱을 고칠 때 (개발용 도구)

- `CLAUDE.md`: Claude Code 로 이 저장소를 열면 자동으로 읽는 작업 안내서입니다. 일하는 방식, 지킬 규칙, 올리는 방법이 적혀 있습니다.
- `dev/`: 자동 검사, 밝은 화면·따뜻한 화면의 디자인 원본, 화면 점검 도구입니다. 앱에는 들어가지 않습니다. 쓰는 법은 `dev/README.md`, 지금 상태와 남은 일은 `dev/STATUS.md` 에 있습니다.
- `app.css` 의 "화면 디자인" 표시 아래는 `dev/themes` 의 원본으로 만든 부분입니다. 그 부분을 고칠 때는 원본을 고친 뒤 `dev` 폴더에서 `npm run themes` 를 돌립니다.
